**T-012 (2026-08-28) ruled the repo hygiene cleanup.** Approved ~57 tracked files for
deletion; executed by `version-control` under **KAN-65**. `HYG-02` split out to **KAN-66**.

**Three refusals worth not re-litigating:**
- **`macos/` stays.** The Analyst's technical reasoning was correct (no build, no registrar,
  `Platform.is*` unaffected) — I rejected only the conclusion. `flutter create --platforms=macos`
  regenerates the folder, not the bundle id / entitlements / signing / sign-in URL schemes.
  5 MB against a day of Xcode archaeology. `windows/` + `linux/` went; symmetry is not a reason.
- **`scripts/generate_token_json.py` stays, and it is not an ASK.** It produces the ten
  `*-theme.json` files under `lib/design_system/tokens/`, shipped as an asset at `pubspec.yaml:223`.
  **General rule: a generator is judged by its output, never by its callers.** See [[verification-lessons]].
- **The `.md` files under `lib/design_system/` and `lib/core/design_system/` were not moved.**
  `MATERIAL3_MIGRATION_GUIDE.md` is cited from live code (`colors/app_colors.dart:10,17`) and
  cross-links its neighbours by relative path. Docs consolidation is its own ticket.

**Pushed to the PO** (business, not technical): the content-engine PDF, `App screenshot/`.

**Why:** *unreferenced* is not *safe to delete* — the inverse of [[load-bearing-measurements]]'s
discipline. Zero inbound references is the expected signature of a hand-run build step and of
tool-convention files (`devtools_options.yaml`).
**How to apply:** before approving any future deletion of a script, ask what it *produces*,
not what calls it.

**Amended 2026-08-28 — `macos/` refusal reversed, scoped to an uncommitted experiment.**
The PO removed the premise: nothing is committed, `origin/Canary` (`ef33ac9`) keeps every
file, recovery is `git checkout origin/Canary -- macos/ windows/ linux/`. Verified the
recovery is complete: `git status --porcelain --ignored -- macos windows linux` returns
**only `!!` (ignored) entries and zero untracked-but-unignored files** — every non-tracked
byte in those folders is `Pods/`, `ephemeral/` and `.plugin_symlinks`, all regenerated by
`flutter pub get` / `pod install`. So the 29 tracked macOS files are the whole of the
non-regenerable content, and git holds all of them.
**The reversal does not extend to a commit.** If deleting `macos/` is ever proposed for
`main`, the original ruling reapplies and needs a fresh decision.
**Live gotcha found in the process:** `scripts/cloudflare-build.sh:21` runs `: > .env` —
running that script locally truncates the developer's real `.env`. Never run it locally;
run `flutter build web --release` with `--dart-define`s directly.
**Second gotcha:** `firebase.json` declares a `macos` platform whose `fileOutput` is
`macos/Runner/GoogleService-Info.plist`. Harmless while the folder is gone, but the next
`flutterfire configure` writes into a directory that no longer exists.
