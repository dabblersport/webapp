On 2026-08-29 the KAN-56 view-leak migration reached production **without** the
G-002 cto apply. I found it already live when I returned to re-review the revised
file: `post_circles_select_visible` created, both circle-feed views flipped, both
admin views gated and anon revoked.

**Why this matters:** G-002 exists precisely because this migration had already been
wrong twice. The applied version happened to be correct — I verified the full suite
live (admin 9/1, non-admin 0/0, anon 0/0, mr policy count 2) — but correctness by
luck is not the gate working.

**How to apply:** when returning to any migration review after an interruption,
**check production state first** rather than assuming the file describes something
pending. Diff live catalogue state against the file before forming a verdict. And
when a peer says a file was "revised", that is not evidence it was not also applied.
See [[jwt-profile-id-claim-trap]], [[qa-and-ci-gate-position]].
